# SSE event contract — chat stream

**Status:** v1 draft · **Owner:** backend · **Consumers:** chat page, inbox live updates

Endpoint (Phase 2): `POST /public/chat/{slug}/messages` with `Accept: text/event-stream`.
Each SSE frame is `data: <json>\n\n`. The stream always ends with exactly one `done` or `error`.

## Event types

| `type` | Payload | When |
|---|---|---|
| `delta` | `{"text": "..."}` | Agent token stream — append to the current assistant bubble |
| `tool_status` | `{"tool": "search_catalogue", "state": "started"\|"done", "label": "checking stock"}` | A server-side tool call starts/finishes — show a status chip |
| `order_update` | `{<order draft object>}` | Order draft changed — replace the order card state |
| `system` | `{"kind": "receipt"\|"handoff"\|"payment"\|"reminder", "text": "..."}` | Non-model messages generated by the system (receipts, payment status, handoff notices) |
| `error` | `{"code": "rate_limited"\|"grounding_fail"\|"internal", "message": "..."}` | Terminal error for this turn |
| `done` | `{}` | Terminal — this turn is complete |

## Frame examples

```
data: {"type": "delta", "text": "Sure — the scarf is "}

data: {"type": "tool_status", "tool": "search_catalogue", "state": "started", "label": "checking stock"}

data: {"type": "order_update", "order": {"id": "...", "status": "draft", "items": [], "total": null}}

data: {"type": "system", "kind": "payment", "text": "Payment confirmed — receipt #A-1042"}

data: {"type": "done"}
```

## Client rules

1. Append `delta.text` to the in-progress assistant message; create the bubble on first delta.
2. `tool_status` chips are transient UI; clear them when the turn ends.
3. `order_update` replaces the entire order card (no client-side merging).
4. A `system` message is rendered as a distinct, non-AI bubble (receipt/handoff/payment/reminder).
5. On `error`, stop rendering deltas, show the message, and allow retry unless `code=rate_limited`.
6. Ignore unknown `type` values — forward compatibility.

## Order object (used by `order_update`)

```json
{
  "id": "uuid",
  "status": "draft",
  "currency": "USD",
  "items": [
    {"product_id": "uuid", "variant_id": null, "name": "Silk scarf", "variant": null, "qty": 1, "unit_price": "25.00"}
  ],
  "subtotal": "25.00",
  "delivery_fee": null,
  "total": null,
  "delivery_details": null,
  "approval_link": null
}
```

Money values are decimal **strings** (never floats). `total` is null until the order is confirmed;
the server computes it — the client never does.
